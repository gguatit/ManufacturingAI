# 10 - WMS

> [!info] 이 파일에서 배우는 것
> - 전산재고와 실제 사용가능재고를 구분한다
> - 수량·위치·품질상태·예약의 네 축을 함께 본다
> - 바코드/RFID 자체가 재고정확도를 보장하지 않는 이유

> [!tip] 30초 요약
> WMS는 "무엇이 어디에 어떤 상태로 누구에게 예약됐는가"를 관리한다. 장비보다 **업무 이벤트마다 정보가 정확히 갱신되는 것**이 더 중요하다.

## 1. 재고를 보는 4개의 질문

| 질문 | 필드 예 | 문제가 생기면 |
| :--- | :--- | :--- |
| 얼마나 있는가? | qty_on_hand | 수량부족/과잉 |
| 어디에 있는가? | location_id | 피킹 지연·분실 |
| 쓸 수 있는가? | quality_status | 보류품 오투입 |
| 누가 쓰기로 했는가? | reserved_order | 이중할당·납기충돌 |

## 2. 입고에서 투입까지 — 이벤트마다 정보 갱신

| 이벤트 | 변경해야 할 정보 | 실패 시 문제 |
| :--- | :--- | :--- |
| 입고 | item/lot, qty, receiving time | 원천이력 누락 |
| 품질검사 | quality_status | 보류품 투입 |
| Put-away | location | 자재 탐색 지연 |
| 예약 | reserved_order, reserved_qty | 이중예약 |
| 피킹 | from/to location, qty | 수량/위치 불일치 |
| 생산투입 | work_order, consumed_qty | 추적성 단절 |
| 반품/잔량 | status, location, qty | 유령재고 |

## 실습 프롬프트

> [!example]- 실물 재고와 사용가능 재고 (클릭해서 펼치기)
> 한빛부품은 전산상 소재 1,200개를 보유합니다. 일부는 품질보류 상태이고 일부는 다른 주문에 예약되어 있으며 일부는 창고 위치가 잘못 등록되어 있습니다. ERP의 재고·구매관리, WMS의 위치·입출고, QMS의 품질상태, MES의 생산투입이 어떻게 연결되는지 설명하세요. 실물 재고, 사용가능 재고, 품질보류 재고를 구분하고, 바코드/RFID 부착만으로 문제가 해결되는지 검토하세요.

## 확인 문제

> [!question]- Q1. "전산 재고 1,200개"만 보고 납기를 약속하면 안 되는 이유를 WMS 관점에서 답하면?
> 위치(location)·품질상태(quality_status)·예약(reserved_order)이 갱신되지 않았을 수 있어 실제 사용가능 수량과 다르다.

> [!question]- Q2. 스캔 장비를 도입했는데 재고정확도가 안 올라간다. 가장 먼저 볼 것은?
> 이벤트별 정보 갱신 절차(입고→검사→Put-away→예약→피킹→투입)가 실제 업무에서 지켜지는지. 장비는 수단이고 정확도는 절차에서 나온다.

> [!quote] 면접 한 문장
> "WMS는 재고 수량만이 아니라 '무엇이 어디에 어떤 상태로 있고 누구에게 예약됐는가'를 관리합니다. 스캔 장비보다 업무 이벤트마다 정보가 정확히 갱신되는 것이 더 중요합니다."

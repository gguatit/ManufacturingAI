# 09 - CMMS

> [!info] 이 파일에서 배우는 것
> - 센서/AI의 이상탐지와 CMMS의 정비업무 관리를 구분한다
> - 점검요청·작업지시·부품·일정·이력을 하나의 흐름으로 설명한다
> - 생산계획과 정비계획의 조정이 필요함을 이해한다

> [!tip] 30초 요약
> 이상탐지는 시작일 뿐이다. **유효성 확인 → 점검 요청 → 작업지시 → 일정 조정 → 수행 → 효과 확인**까지 이어져야 정비가 완성된다.

## 1. 이상에서 정비완료까지

| 단계 | 역할 | 확인정보 |
| :--- | :--- | :--- |
| 1 이상 감지 | 센서/규칙/AI가 평소와 다른 패턴 표시 | 진동, 온도, 부하, 시간 |
| 2 유효성 확인 | 센서오류·운전조건 변화 확인 | 센서상태, 속도, 제품, 추세 |
| 3 점검 요청 | CMMS에 증상과 우선순위 등록 | asset_id, symptom, priority |
| 4 작업지시 | 담당자·작업·부품·허가·기한 정의 | work_order, parts, permit |
| 5 일정조정 | 생산관리와 정지가능시간 합의 | MES schedule, due date |
| 6 수행·완료 | 정비결과와 교체부품 기록 | start/end, cause, action |
| 7 효과확인 | 진동/정지/고장 지표 재확인 | trend, downtime, recurrence |

> [!note] 부록 B-4 예시 데이터
> M03 설비: 08:00 진동 2.1 / 10:00 진동 3.0 / 12:00 진동 4.2 + 알람 Y "점검 필요" / 14:00 진동 4.0 + 부하 42%. 진동 추세로 이상은 보이지만, **원인 미확정** 상태로 점검을 요청하는 흐름이 맞다.

## 2. 정비전략 비교

| 유형 | 설명 | 장점/주의 |
| :--- | :--- | :--- |
| 사후정비 | 고장 후 복구 | 단순하지만 비계획정지 위험 |
| 예방정비 | 주기·사용시간 기준 | 계획 가능, 과잉정비 가능 |
| 상태기반정비 | 현재 상태 임계/추세 기준 | 필요시점 판단, 센서 신뢰성 중요 |
| 예지정비 | 데이터모델로 미래 위험 예측 | 선행시간 확보 가능, 모델검증 필요 |

## 실습 프롬프트

> [!example]- 진동 증가 대응 (클릭해서 펼치기)
> 한빛부품 가공설비에서 평소보다 높은 진동이 감지되었습니다. 아직 고장 원인은 확인되지 않았고 생산도 진행 중입니다. 센서와 AI 이상탐지, CMMS, 정비담당자, 생산관리자의 역할을 구분하세요. 이상 확인→점검 요청→작업지시→부품 준비→정비 일정 조정→정비 결과 기록→효과 확인의 흐름을 표로 작성하세요. 진동 증가만으로 특정 부품 고장을 확정하지 마세요.

> [!example]- 개발직무 확장 — CMMS Work Order 필드 (클릭해서 펼치기)
> 교육용 CMMS 정비 작업지시의 필드를 asset_id, maintenance_wo_id, detected_at, symptom, priority, requested_action, technician, required_part, planned_start, actual_end, result, root_cause_status로 제한해 설계하세요. 각 필드가 어떤 업무 질문에 답하는지 설명하세요.

## 확인 문제

> [!question]- Q1. AI가 "베어링 고장 확률 87%"라고 알려줬다. 바로 부품을 교체 주문해도 되나?
> 아니다. ① 유효성 확인(센서오류·운전조건 변화) ② 점검으로 실제 상태 확인 ③ 생산일정과 정지시간 협의 후 작업지시. AI 이상탐지는 "후보 신호"다.

> [!question]- Q2. 상태기반정비와 예지정비의 차이는?
> 상태기반은 현재 임계·추세로 "지금 점검이 필요한가"를 판단하고, 예지정비는 모델로 "미래 위험"을 예측해 선행시간을 확보한다. 예지정비는 모델 검증이 전제다.

> [!quote] 면접 포인트
> "센서·AI는 이상탐지, CMMS는 정비업무 관리"라는 경계를 사례로 구분해 말할 수 있어야 한다.

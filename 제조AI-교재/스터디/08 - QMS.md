# 08 - QMS

> [!info] 이 파일에서 배우는 것
> - QMS를 검사결과 저장이 아니라 부적합통제·추적·원인검증·시정조치로 이해한다
> - 확인된 사실과 원인 가설을 구분한다
> - PLM·MES·WMS 데이터를 품질사건에 연결한다

> [!tip] 30초 요약
> 불량을 찾으면 먼저 **격리**, 그다음 **추적**, 원인은 **가설→데이터로 검증**. 상관관계는 원인 확정이 아니다.

## 1. 품질문제 대응 6단계

| 단계 | 핵심 질문 | 필요 데이터 |
| :--- | :--- | :--- |
| 1 기준 확인 | 어떤 도면·공차·검사방법이 유효한가 | revision, inspection_spec |
| 2 측정 신뢰성 | 측정값을 믿을 수 있는가 | gauge_id, calibration, method |
| 3 부적합 통제 | 어떤 로트를 격리해야 하는가 | lot, qty, disposition |
| 4 추적 | 어떤 자재·설비·조건이 연결됐는가 | material_lot, equipment, process |
| 5 원인 검증 | 가설을 어떤 데이터로 확인할 것인가 | tool life, temp, operator, sample |
| 6 시정·효과 | 다음 로트에서 재발이 줄었는가 | action, owner, due, recurrence |

## 2. 사실과 가설의 분리

| 구분 | 예 |
| :--- | :--- |
| 확인된 사실 | 측정값이 공차를 초과했다 / lot L2401 / 설비 M03 / B판 도면이 적용되었다 |
| 원인 가설 | 공구마모 / 소재편차 / 측정기 이상 / 작업조건 차이 / 고정구 문제 |
| 추가 확인 | 공구수명, 소재성적, 측정기 교정, 제품Mix, 작업속도, 표본수 |

## 실습 프롬프트

> [!example]- 치수불량 추적 (클릭해서 펼치기)
> 한빛부품의 최종검사에서 일부 제품의 치수 불량이 발견되었습니다. 어느 자재와 설비에서 만들어졌는지 즉시 확인하기 어렵습니다. QMS 관점에서 PLM·MES·WMS와 연결해 확인할 정보를 제시하세요. 제품/로트, 적용도면, 검사기준, 측정기 상태, 자재이력, 가공설비, 공정조건, 재작업 이력을 포함하세요. 반드시 "확인된 사실"과 "원인 가설"을 구분하고 데이터 없이 원인을 확정하지 마세요.

> [!example]- 개발직무 확장 — 역추적 조회 순서 (클릭해서 펼치기)
> 불량 로트 finished_lot=FG-240918-01에서 역추적할 때 필요한 조회 순서를 SQL을 실제 실행하지 않는 의사코드 형태로 작성하세요. finished_lot → inspection → work_order → equipment/process → material_lot → revision 순으로 연결하고, 각 단계에서 조회 키와 확인 목적을 설명하세요.

## 확인 문제

> [!question]- Q1. "설비 M03에서 불량률이 높다"에서 사실과 가설은?
> "M03의 불량률이 높다"는 **관측된 사실**(상관관계). "M03이 원인이다"는 **원인 가설**이다. 원인 확정 전에 표본수·제품Mix·측정기·조건 등 교란 요인을 확인해야 한다.

> [!question]- Q2. 부적합을 발견했을 때 가장 먼저 할 일은 원인 분석인가?
> 아니다. 먼저 **격리(부적합 통제)**다. 영향 범위를 확정해 추가 유출을 막은 뒤 추적·원인검증 순서로 간다.

> [!quote] 면접 질문
> "불량률이 특정 설비에서 높다는 상관관계를 발견했습니다. 그 설비가 원인이라고 결론 내리기 전에 무엇을 확인하겠습니까?"
